# 구현과 검증 규칙

SwiftPM 대상과 기존 최소 macOS 14를 유지한다. 새 외부 의존성이나 도구 추가는 확인이 필요하다. 공통 해석은 Core, 앱 수명·현지화·창은 앱 계층에 둔다. 공급자 설정과 새 전역 Opencodex 경로는 서로 덮어쓰지 않는다.

Swift 6 엄격한 동시성, 명시적 self, 공백 4칸, 120자 폭과 저장소 SwiftFormat·SwiftLint 설정을 따른다. SwiftUI 상태는 Observation과 @Observable·@State·@Bindable을 우선한다. XCTest 경로는 기존 묶음을 따르고 Swift Testing 이름은 문장형 backtick을 사용한다. 모델 이름은 출시된 이름이나 명백한 가상 이름만 쓴다.

필수 작업과 선택 작업을 형제 async let로 묶지 않는다. 순서대로 기다리거나 모든 자식을 정리하는 task group에서 필수 실패를 드러내고 선택 실패를 명시적으로 격리한다. swift_task_dealloc·asyncLet_finish_after_task_completion 충돌은 근처 async let의 수명부터 조사한다.

공급자 카드에는 다른 공급자의 신원·요금제 자료를 쓰지 않는다. Claude CLI status line은 사용자가 명시적으로 켠 기본 꺼짐 JSON 소스 외에는 사용량 해석 정본으로 사용하지 않는다. 키 생성 결과는 목록·설정·공유 미러의 저장 가능한 모델에 합치지 않는다.

설정 테스트는 메모리 기본 설정을 주입한다. app-group 이전 테스트는 두 snapshot URL·합성 홈·제한된 기록용 FileManager까지 주입한다. UUID defaults suite나 Keychain 억제 플래그만으로 파일·기본 설정 검색 영역이 격리되었다고 보지 않는다. 일반 SettingsStore 테스트는 공유 defaults 탐색이나 app-group 이전을 시작하지 않는다.

테스트는 변경한 동작에 맞는 집중 묶음부터 실행한다. 완료 전 집중 테스트와 make check를 실제로 통과시킨다. 실패·새 변경·관련 우려가 없으면 같은 전체 검사를 보고용으로 반복하지 않는다. 장시간 전체 묶음은 PR CI 또는 필요할 때 백그라운드에서 실행하며 일반 작업을 막는 필수 조건으로 확대하지 않는다.

SwiftPM 산출물은 checkout 사이에 복사하지 않는다. 각 checkout의 증분 캐시를 사용하며 오염이 확인되거나 비교가 필요할 때만 지운다. 테스트 실행기·CI 변경은 기존 전체 테스트 목록·기한·실패 처리·캐시 검증·안전한 재빌드 계약을 보존한다.

UI 증거는 새로 빌드한 코드와 합성 연결에서 얻는다. 메뉴 막대 자동화는 실제 화면과 아이콘을 먼저 확인하고 화면 밖 좌표의 성공 반환을 클릭 증거로 인정하지 않는다. AppKit 상태·메뉴 테스트는 가능한 경우 순수 모델을 쓰고 실제 메뉴 구성 자체를 바꿀 때만 라이브 객체를 만든다. Widget·Tahoe 문제의 실제 화면 검증은 별도 macOS VM을 사용할 수 있다.

커밋은 변경 목적이 드러나는 짧은 명령형 문장으로 나누고 PR에는 결과 동작·실행한 검증·UI 증거·관련 근거를 적는다. 포크 장기 브랜치 gujo와 원본 steipete 저장소를 구별한다. 기존 운영 브랜치 통합·push·설치본 교체·릴리스는 사용자의 해당 범위 승인 후에만 한다.

릴리스 자격과 Sparkle 키를 다른 앱의 값으로 대체하지 않는다. 기존 공개 키에 대응하는 개인 키를 CI에서 사용하고 배포 완료는 산출물·feed·tap 전체가 일치할 때만 보고한다.
