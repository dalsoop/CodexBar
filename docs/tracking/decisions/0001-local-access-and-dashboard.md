# 로컬 키 관리와 기존 대시보드

## 상황

사용량·허브 계정을 CodexBar에서 보다가 데이터 키 발급을 위해 다른 앱으로 옮겨야 했다. 사용자는 빠른 전용 키 화면과 기존 대시보드를 모두 원했다. 허브에 연결된 client도 자료를 읽을 수 있지만 로컬 관리 권한을 가진 것은 아니다.

## 결정

CodexBar에 로컬 hub·standalone용 목록·생성·복사·이름 변경·폐기를 제공하고 기존 대시보드를 별도 내장 창에 연다. 고급 범위 편집·교체는 기존 웹 UI를 사용한다. 웹 세션은 전용 비영구 저장소와 창 수명으로 제한한다.

설치된 Opencodex 2.88.0의 rename CLI에는 ID가 사라지면 이름으로 재검색하는 동작이 있다. 이름 변경만 제한된 보조 실행기에서 같은 설치의 기존 관리 클라이언트를 사용해 정확한 ID로 PATCH한다. 관리 인증은 기존 클라이언트 내부에 둔다.

## 대안과 이유

외부 대시보드 링크만 두면 반복 키 작업을 앱에서 처리하려는 요구를 충족하지 못한다. 모든 웹 기능을 네이티브로 복제하면 서버 기능과 권한 정책을 중복 관리해야 한다. client에 새 원격 관리 자격을 배포하면 현재 로컬 허브 범위를 넘어선다.

기존 rename CLI 앞뒤로 목록을 확인하는 방법은 삭제와 이름 충돌 사이의 경쟁 상태를 막지 못한다. 관리 토큰을 CodexBar가 직접 읽어 HTTP를 호출하는 방법은 비밀값 보관 경계를 넓힌다. 제한된 기존 클라이언트 재사용은 이 두 문제를 피하지만 지원 설치 구조를 확인해야 한다.

영구 WebKit 저장소는 창을 닫아도 인증 상태가 남는다. 비영구 저장소를 선택하여 재열기 때 인증이 다시 필요할 수 있는 편의 비용을 받아들였다.

## 결과

다른 Mac의 원격 관리나 OpenClaw 자동 연결은 현재 제공하지 않는다. 이름 변경은 지원 설치가 아니면 사용할 수 없고 CLI로 대체하지 않는다. 새 키 비밀값은 결과 화면을 닫으면 복구하지 못하며 재발급을 자동화하지 않는다. 대시보드 창을 닫으면 세션을 버린다.
