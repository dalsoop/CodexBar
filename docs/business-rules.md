# 계정과 API 키

공급자 계정은 Claude·Codex·Grok 등의 사용량과 접속 자격을 가진다. 데이터 API 키는 Opencodex 요청에 쓰는 별도 자격이다. 계정 카드의 신원과 한도는 해당 공급자의 자료로만 표시하며 데이터 키 생성으로 공급자 로그인이나 OpenClaw 설정이 바뀌지 않는다.

CodexBar 자체 HTTP 대시보드의 bearer token도 Opencodex 데이터 키·관리 인증과 다른 자격이다. 이름에 대시보드가 들어가더라도 서버와 권한을 서로 바꾸어 적용하지 않는다.

허브 계정 사본은 읽기용 자료다. 사본이 있거나 목록 명령에 응답했다고 로컬 관리 권한이 생기지 않는다. 보고된 역할이 hub 또는 standalone인 기기만 자신의 로컬 키를 관리한다. client는 허브에서 관리하도록 안내하며 알 수 없는 역할을 허브로 추측하지 않는다.

키의 ID는 고정 식별자이고 이름은 바뀔 수 있는 표시값이다. 이름이 같은 키도 ID가 다르면 별개다. 중복 ID나 잘못된 필수 메타데이터는 변경 대상 목록으로 쓰지 않는다. 이름 변경은 공급자·모델 제한을 보존한다. 폐기는 선택한 ID 하나만 대상으로 하며 사용자의 확인 전에는 실행하지 않는다.

생성은 이름을 입력하고 생성 버튼을 누른 때에만 시작한다. 원문에 제어 문자가 있거나 CLI 옵션으로 해석되는 이름은 거절한다. 앞뒤 공백을 뺀 이름은 비어 있지 않고 UTF-16 단위 64 이하여야 한다. 생성 결과의 새 비밀값은 현재 실행의 전달 화면에만 두며, 전달 화면을 닫은 뒤 조회로 복구하지 않는다.

네이티브 변경은 앱 전체에서 하나만 실행한다. 화면 이동으로 복제하거나 다시 시작하지 않는다. 변경 응답을 확인할 수 없으면 확인 필요로 표시하며 자동 재발급·폐기·재시도를 하지 않는다. 변경 성공 후 조회만 실패했으면 성공한 변경과 실패한 갱신을 따로 표시한다. 갱신 실패 후 남은 목록은 볼 수 있지만 변경 대상은 될 수 없다.

통계는 유효한 귀속 시작 시각과 모호하지 않은 사용 자료가 함께 있을 때만 숫자로 표시한다. 값 없음은 확인할 수 없음, 실제 빈 기록은 기록된 사용 없음으로 구별한다. 불완전·잘린 기록은 그 상태를 표시하고 없는 숫자를 0이나 비용으로 만들지 않는다. 인증을 건너뛰는 loopback 호출은 키별 귀속을 보장하지 않으므로 발급만으로 사용량 분리를 약속하지 않는다.
